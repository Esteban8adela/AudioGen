# Supabase (AudioGen)

SQL migrations live in `migrations/`. Job queue remains Redis (see `worker/`);
the optional `jobs` table is an audit trail only.

## Apply migrations

### Option A — Supabase CLI (recommended)

```bash
# From repo root, after `supabase login` and linking the project:
supabase link --project-ref YOUR_PROJECT_REF
supabase db push
```

Or run a specific migration file against a linked remote:

```bash
supabase db execute --file supabase/migrations/001_initial_schema.sql
```

### Option B — SQL Editor

1. Open the Supabase Dashboard → SQL Editor
2. Paste the contents of `migrations/001_initial_schema.sql`
3. Run the script once on a fresh project

### Option C — Local Supabase

```bash
supabase start
supabase migration up
```

## Security notes

- RLS is enabled on all `public` tables.
- Credits / plan / `stripe_customer_id` cannot be changed by clients (trigger + no insert policies).
- Use `debit_credit_for_book_generation` for ACID credit spends.
- Book inserts and privileged writes should go through Next.js Route Handlers using the **service role** key (never ship that key to the browser).
- Catalog view `catalog_books` excludes DMCA-flagged / non-ready works.

## Minimal config

A full `config.toml` is generated by `supabase init` if you need local emulation.
This folder intentionally keeps migrations + docs first for Paso 1.
